# EnoughVisuals 2.6 — static security and privacy review

Review target: the user-provided `enoughvisuals-2.6(2).jar` (SHA-256 `e3598cb6b2ee938bf4890495269cc5a7da6e825d97898874cc618beb3b3089d1`).

This is a static inspection of archive contents and selected Java bytecode. The JAR was not launched. This review is not a malware verdict or a guarantee that every class and embedded dependency is safe.

## Confirmed privacy-sensitive behavior

### Device identifier and remote sync
- `EnoughCore.initializeClient()` starts `RemoteConfig` automatically during client initialization.
- `RemoteConfig` starts a background polling thread. Its bytecode defines a normal poll interval of 5 seconds and a multiplayer interval of 300 ms.
- `RemoteConfig.buildRequest()` constructs a JSON request containing `hwid`, Minecraft username, Minecraft UUID, mod version and a list of installed/enabled modules. It can also append server icon data, game-server information, and sync data from emotions, cosmetics, graffiti and web panels.
- `hwid` is generated by `HwidUtil`. The inspected code attempts to read the Windows registry MachineGuid, macOS platform UUID, or Linux machine-id. If unavailable, it creates and persists a random identifier under `.enoughvisuals/hwid`; the resulting value is combined with the CPU architecture and SHA-256 hashed.
- `LauncherNetworkClient` defines the remote sync endpoint as `https://api.enoughvisuals.fun/v1/sync` and sends the request body with an HTTP POST.
- The remote response is used for module blocking, client blocking, update requirements, ban state, roles and server configuration.

**Porting decision:** do not copy this HWID collection, automatic telemetry, remote module blocking, ban enforcement, or remote configuration flow into XakaVisuals.V2. These are not required for local visual features. Any future Xaka network feature must be separately designed, opt-in, documented, and limited to the data needed for that feature.

## Other components requiring isolation/review
- Event-feed code makes network requests for server-specific event information.
- Discord presence code and media-player integration interact with local desktop services.
- WebPanels use MCEF and bridge browser content into the game. Browser pages and scripts must be treated as untrusted.
- The archive bundles five nested JARs: FunTimeEventsSDK, cosmetic, jDRPC, mcef and pulse-cosmetics.
- The archive also contains two Windows DLLs, including a CEF audio native library and a media-player integration DLL.
- The archive's `fabric.mod.json` declares the mod license as `All rights reserved`; do not copy bundled third-party dependencies or assets blindly. Keep permission and attribution requirements separate from technical compatibility.

## Static indicators checked
The archive contains expected process/network/reflection API references in several components. In particular, `ProcessBuilder` is used by `HwidUtil` to query OS machine identifiers (Windows registry and macOS `ioreg`). This is privacy-sensitive device identification, not by itself proof of malware. Network APIs are present in the remote config, event-feed, launcher and browser components.

No code from the JAR has been executed as part of this review.

## Safe porting approach
1. Prefer independent local client-side features (HUD, rendering, particles, visual settings and local cosmetics).
2. Reimplement behavior against the XakaVisuals codebase rather than importing opaque compiled classes.
3. Do not bundle nested JARs or native DLLs until each dependency, license, provenance and runtime need has been reviewed.
4. Keep remote communication disabled by default; require explicit user opt-in for any future online feature.
5. Build and inspect each feature batch in CI, then perform a separate Minecraft 1.21.4 launch test.
